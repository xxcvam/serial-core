## 01 产品目标与核心用户场景

### 1.1 产品目标（三层，按可验证性从高到低）

| 层 | 目标 | 判据 | 不成立的后果 |
| --- | --- | --- | --- |
| 商业 | 卖出可独立演奏的实体乐器 | G1 四项支付条件同时成立；G2 后有真实样机与小批量成本 | 硬件不能只做"概念载体"，否则退化为周边 |
| 体验 | Same Serial → Same Musical Structure | 结构哈希逐字节一致（音高、时值、次序、初始结构、协议内参数） | 一旦分叉，Serial Card 的全部叙事失效 |
| 传播 | 一张卡 → 扫码 → 30 秒 → 定金 | 扫码率 ≥ 20%、听完率 ≥ 30%、≥ 3 名非熟人付费、7 天退款率 < 50% | 卡降级为宣传物料，不再承载"作品身份" |

三点口径纪律：

- ¥2,999 是**内部测试值**，不是定价。在 G1 证据出来前，任何对外物料不得出现该数字作为售价。
- "可复现"只承诺结构，不承诺逐样本音频、不承诺逐帧视觉。跨芯片、跨声卡、跨浏览器的波形差异不是缺陷。**v1.2 追加：也不承诺视觉粒子、材质、PCB 图案逐帧/逐台一致（§5.4 已明确首批统一 PCB）。**【v1.2 变更】
- 目标不是"做出最酷的 3D"，是"让人愿意为一台能自己出声的机器付钱"。

### 1.2 核心用户：三个角色，不是"用户们"

| ID | 角色（具体到人） | 场景 | 现在用什么笨办法 | 换的理由 | 本阶段是否服务 |
| --- | --- | --- | --- | --- | --- |
| U1 | 数字文化原住民：30–45 岁，经历过注册机/Cracktro/Demoscene/Tracker，现在有稳定收入，买过硬件 groovebox | 想要"输入一串编号，机器自己长出一段结构"的仪式感，并且能摆在桌上摸 | 纯软件（Tracker、VCV）没有实体感；纯硬件（Elektron、Polyend）没有"编号解锁世界"的叙事 | 一台不接电脑也能响的机器 + 可收藏的编号 | ✅ G1 主力，G2 核心 |
| U2 | 视听演出创作者：做现场 A/V，熟悉 TouchDesigner/Resolume | 演出时音画要对拍，现场不能掉拍 | 手工对拍、MIDI 触发、录好的视频轨；掉帧就露馅 | 音频时钟在硬件上，视觉只是订阅者，掉帧不掉拍 | ⚠️ G3 才服务，G1 不承诺 |
| U3 | 现场路过者：在场景里被递到一张卡 | 30 秒内决定要不要留联系方式/付定金 | 扫一个二维码听一段音频，通常听完就关 | 编号 → 声音 → 可付定金的完整闭环 | ✅ G1 唯一转化对象 |

裁决含义：**G1 的页面是给 U3 用的，不是给 U1 看的。** U1 的深度体验（旋钮、Crack、连续演奏、可触摸的面板工艺）在 G1 不存在，也不该用 G1 页面或提前打样的面板去模拟它，否则会制造"已可演奏"的误读。【v1.2 变更 · 补"面板工艺"一项】

### 1.3 三种体验的边界（硬边界，逐列可核对）

| 维度 | Explore & Preview（购买前） | Connect & Perform（购买后） | Hardware-led A/V（舞台） |
| --- | --- | --- | --- |
| 阶段 | G1（精简版）→ G2 增强 | G2 | G3 |
| 谁生成事件 | 浏览器本地，按同版本 S1 协议 | 硬件 | 硬件 |
| 谁发声 | 浏览器 WebAudio | 硬件（权威） | 硬件（权威） |
| 谁有写权限 | 无（只读生成结果） | 硬件；网页只能发 Edit Request，收到 ack 才算生效 | 无（只读订阅 transport 与音频特征） |
| 连接要求 | 无 | USB 或局域网（支持矩阵内） | 局域网 |
| 断连时行为 | 不适用（本来就离线） | 降级为本地 Preview，**声音不停** | 视觉黑场/降质，**音频不停** |
| 可以说的 | "同一套算法在浏览器里跑出来的试听" | "现在同步的是这台机器" | "画面跟着这台机器的演奏走" |
| 不可以说的 | "和你的机器实时同步"；"这就是成品外观" | "网页可以替代硬件发声" | "音频由网页输出" |

三条不可越界（写成页面文案的 review checklist）：

1. **Preview 不假装已连接。** 无设备徽标、无"已同步"字样、无"连接成功"提示。页面角落必须常驻阶段声明（未完成样机 / 非上市商品）。
2. **Connected 不夺权。** 网页永不成为 transport 权威，永不静默改写 Seed；版本不匹配时阻断并提示，不"尽力兼容"。
3. **A/V 不接管音频。** 视觉掉帧、降质、暂停、一键黑场，都不得改变音频时钟或输出。

### 1.4 场景 → 付费理由映射（谁为哪一段付钱）

| 付费理由 | 归属场景 | 若这条不成立 |
| --- | --- | --- |
| "它能自己出声，不接电脑" | 实体（Offline） | 产品退化为软件 + 外壳，定价逻辑崩塌 |
| "编号能复现，能收藏、能送人" | Serial Card | 卡变成普通名片，传播链断掉 |
| "面板/PCB 是这台机器的语言，不是贴纸" | 实体（工业设计）【v1.2 变更 · 新增】 | 面板 Art 退化为装饰，8.0 人日属沉没成本；此时砍 G2-A，不影响任何软件判定线 |
| "网页能看到它内部的世界" | Preview / Connected | 只损失传播效率，不损失核心价值 → 因此它排在 G1 之后 |
| "现场音画不出事" | A/V | 只影响 B 端场景，不影响 C 端购买 → 因此它排在 G3 |

这张表就是优先级的第一性依据：**越靠上的理由，越早验证；越靠下的理由，越晚投入。**【v1.2 变更 · 新增第 3 行】

### 1.5 表述纪律增补（v1.2 专项）

v1.2 引入了一组"设计语言共用"的表述，风险不在实现，在**被读成已实现**。以下三条与 1.3 的"不可以说的"同级执行：

1. **共用语法 ≠ 按 Seed 生成。** 可以说"实体面板、Web 光路、卡面共用一组节点/线路形态"；不可以说"每台机器/每张卡按 Serial 生成独立图案"。
2. **visual_manifest 未冻结，禁止写成能力。** 详见 §5.4 禁用语清单。
3. **打样 ≠ 定稿。** 首件实物只证明"可制造、可装、可读"，不证明量产工艺、不证明成本、不证明光学/ESD/氧化结论（v1.2 §5.4 已把设计验收与电路可靠性、光学效果、成本验证分开记录，本文照此执行）。

【v1.2 变更 · 本节整节新增】

### 2.2 为什么 G1 砍掉 Three.js 与 Rodin（三条理由，按权重排序）

1. **机会成本。** 同样 12 人日，问"愿不愿意付 ¥150 可退定金"的边际信息量，远大于问"渲染好不好看"。付款决定由"30 秒声音 + 编号叙事"驱动，不由画面精度驱动——这是可被 G1 证伪的假设，所以必须先单独测它。
2. **交付风险不可控。** 概念资产清理到可上线是 5–6 人日/件（05A.5 基线），且返工不可预测。一旦进入 G1，12-19 档期与 ¥5,500 现金上限会同时失守。
3. **证据污染。** G1 若同时上 3D，扫码率上升无法归因到声音还是画面，判读口径直接作废——这比做不完更贵。

裁决策略落点：G1 的构建期断言必须能拦住 `three`、`*.glb`、`*.hdr`、`*.ktx2` 进入 `/` 与 `/s/*` 的 chunk（Web 规划 §5.2 已定义手段，此处只确认它是**验收项**而非建议）。

**v1.2 为 PCB Art 补一条同构理由（第四条，权重排在第一之后）：**【v1.2 变更】

4. **G1 加 PCB Art 会同时污染证据与现金。** 面板版稿依赖结构尺寸（旋钮位置、紧固、屏开窗、接口），而 G1 期间结构未冻结 → 版稿必然返工；打样是串行的物理周期（一轮 8–17 自然日），塞进 11-15 到 12-19 的窗口等于用日历赌一块没定稿的板。G1 要的是"愿不愿意付钱"，不是"面板好不好看"。

### 2.3 为什么 G2 先协议、后画面

风险表第一顺位不是"画面不够好"，是"Digital Twin 只是一张漂亮模型"。所以 G2 的顺序被锁死：

```
Link 三实现 → 握手/版本阻断 → 全量 snapshot → transport 订阅 → 控件映射 → 形态 token 对齐 → 最后才是材质精修
```

如果 G2 只能交付一半，交付"旋钮动了网页 150ms 内有反应"，砍掉"网页很好看"。反过来交付等于做了一张会动的海报。

**v1.2 插入位置裁决**：面板/PCB Art 首件是**独立轨道**，不在此串行链上了——【v1.2 变更】

- 它依赖的是**结构尺寸冻结**（Fusion 360 / ECAD，即 v0.1 ★7 的 CAD 时间点），不是 Web 的 Link 进度；
- 因此 G2-A 与 G2-W **并行**，唯一硬约束是"打样下单必须在结构尺寸冻结之后"；
- 它在 G2 内的排序是第 4 顺位（Link → 状态机 → 控件映射 → 面板首件 → 视觉精修），但"顺位"只决定**人力抢占顺序**，不决定**判定线归属**：面板不合格不得阻断 G2-b。

### 2.4 为什么 G3 才做 Generative World

G3 的验收对象是**现场 30 分钟不出事**，不是截图好看。现场失败的代价是公开的，因此 G3 的门槛是彩排、降级与黑场，不是视觉复杂度。G3 的任何视觉升级都不得以"提高音频链路风险"为代价。

**v1.2 追加**：G3 才是"Web 光路与实体面板共用语法"真正兑现的阶段——G2 只交 token 表与首版对齐，G3 才做 16-step 几何、程序化雕塑与光路的完整映射。把 G3 的视觉预期提前压到 G2，是 v1.2 最容易被误读的一处。【v1.2 变更】

### 4.3 G2：重估（13.0 装不下）

#### 4.3.1 直接结论

**装不下。** 三条独立理由，任一成立即否决"13.0 内消化面板首件"：

1. **口径理由（最硬）**：v0.1 §4.1 把 G2 定义为"仅 Web 侧"，把 PCB 版稿与打样塞进去，等于同时破坏"13 是 Web 口径"和"13 不含工业设计"两条定义。口径一旦混，后续所有排期与对外表述都会跟着错。

### 6.4 本文档的证伪条件（什么情况下这份文档该被推翻）

- G1 扫码率与听完率达标，但付费为 0 → "声音 + 编号叙事足以驱动付费"被证伪。此时正确动作是重做价值主张，**不是加大 3D 投入**。
- G1 未达标，但非投放渠道（自然转发、场外扫码）占比高 → 是渠道判断错了，不是产品错了；重做渠道，不动产品。
- G2 上线后旋钮映射的采用率长期 < 3% → "Digital Twin 是核心体验"被证伪，Web 退回纯预览，省下的 16 人日不投 G3。
- 若 G1 期间硬件提前做出可演奏 Alpha，且现场反馈明显强于页面 → 优先级从"传播"切回"硬件可用性"，G1 的卡与埋点降级为辅助。
- **【v1.2 新增】面板首件两轮不合格，或单件打样成本超出 N1 上限 2 倍** → "PCB Art 可在 V1 阶段低成本落地"被证伪。此时撤回至"统一丝印、零版图改动"，8.0 人日余额转 G2-W 或 G3；同时把被推迟的 G3 视觉精修捡回来（当初正是为它让的路）。
- **【v1.2 新增】若"形态 token 表"在 G2 结束时仍需三个消费方各自解释差异** → "共用设计语言"被证伪，它只是三张不同的图。此时停止在 G3 追加形态映射，Web 与卡面各自独立迭代。
