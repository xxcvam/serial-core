## 05A.1 材质体系与 PBR 规范

### 05A.1.1 材质清单（锁定 5 个，禁止扩张）

美术方向是 Industrial Archaeology × Demoscene × Procedural Sculpture：深黑与烟熏金属为底，乳白聚合物为主体，精密结构做骨架，局部荧光做事件反馈。材质数量直接等于 Draw Call 和 shader 变体数量，**上限 5 个基础材质 + 1 个屏幕材质**。

| ID | 材质名 | 视觉职责 | metalness | roughness | 备注 |
|---|---|---|---|---|---|
| M1 | `M_SERIAL_SmokedMetal` | 机身主壳、底板 | 0.85–1.0 | 0.28–0.42 | 带拉丝/喷砂各向异性观感，用 roughness 变化贴图伪造，不用 anisotropy |
| M2 | `M_SERIAL_MilkPolymer` | 面板、旋钮、键帽 | 0.0 | 0.42–0.55 | 唯一允许开 `clearcoat` 的材质，clearcoat 0.3–0.6 / clearcoatRoughness 0.35 |
| M3 | `M_SERIAL_PrecisionSteel` | 轴、螺丝、接口框 | 1.0 | 0.14–0.22 | 高光锐利，是画面唯一「硬高光」来源 |
| M4 | `M_SERIAL_EmissiveAccent` | 荧光指示、Crack 状态 | 0.0 | 0.6 | emissive 强度由状态机驱动（见 05A.4.4），不做贴图常亮 |
| M5 | `M_SERIAL_DarkRubber` | 脚垫、缝隙遮挡 | 0.0 | 0.75–0.9 | 全黑，靠 AO 出形，不参与高光 |
| M6 | `M_SERIAL_ScreenGlass` | 4.3″ 屏面 | 0.0 | 0.03–0.08 | 仅此一处允许 `transmission`；移动端降级为不透明黑 + 屏幕自发光贴图 |

**【v1.2 变更】** PCB Art 不新增材质 ID。阻焊、丝印、沉金、露铜是**同一块面板上的逐像素材质差异**，由 M2 面板实例通过 `metallicRoughnessTexture` + `clearcoatMap` + ArtMask 表达，实例数仍为 6。参数表见 05A.1.4。

**Shader 选型（three.js）**

- M1/M2/M3/M5：`MeshStandardMaterial`。
- M2：`MeshPhysicalMaterial` + clearcoat。
- M6：`MeshPhysicalMaterial` + transmission，**仅在 `capabilities.isWebGL2 && !isMobileGPU` 时启用**；否则回退 `MeshStandardMaterial`。
- 禁用：`MeshPhysicalMaterial` 的 iridescence / sheen / anisotropy 扩展；`MeshLambertMaterial` / `MeshPhongMaterial`（与统一光照模型冲突）。
- 禁止在 GLSL 里手写 `pow(NdotL, n)` 型自定义光照——所有材质走同一套 PBR，才能做一致性比对。
- **【v1.2 变更】** 同理，PCB Art 的介质差异**禁止**用自定义 shader 实现；只允许走贴图通道。理由与上条相同：任何绕开统一 PBR 的分支，都会让 05A.4.2 的 ΔE 不可比。

### 05A.1.2 贴图规范

**通道打包：一张 ORM 同时供 occlusion / roughness / metalness**（glTF `occlusionTexture` 与 `metallicRoughnessTexture` 共用同一图像，three.js 里分别赋值即可，不重复上传）。

| 贴图 | 通道 | 色彩空间 | 分辨率（LOD0/1/2/3） | 生成方式 |
|---|---|---|---|---|
| BaseColor | RGB | sRGB | 2048 / 1024 / 512 / 256 | 程序化生成，Rodin 贴图仅作宏观变化参考 |
| ORM | R=AO, G=Roughness, B=Metalness | Linear (NoColorSpace) | 同 BaseColor | R 由 AO 烘焙，G/B 由材质定义 + 细微噪声 |
| Normal | RGB, OpenGL +Y | Linear | 2048 / 1024 / 512 / — | 高模→低模烘焙 |
| Emissive | RGB | sRGB | 512 | 仅 M4，白底遮罩 |
| **【v1.2 变更】** ArtMask | R=丝印遮罩, G=金属介质（沉金/露铜）, B=介质二级区分, A=保留 | Linear (NoColorSpace) | 1024 / 512 / 512 / — | 程序化生成（05A.7）；**管线侧资产，不入 runtime 包** |

**ArtMask 的三条使用纪律（【v1.2 变更】）**

1. **用途仅三件**：① 自动化断言（覆盖率、禁区侵入、最小特征）；② 回归基线（遮罩 hash）；③ 重生成缓存（换调色板时只重算色层，不重跑光栅）。
2. **不挂到 shader 上**。运行时面板仍是单张 BaseColor，Art 已在生成期合成进去。挂 ArtMask 只会多一次采样和一条 UV 通道，换不来 Draw Call 收益——面板本来就 1 个 DC。
3. **不复用 BaseColor 的 alpha 通道**存放遮罩。KTX2 ETC1S 的 alpha 质量不可控，且 OPAQUE 材质下 alpha 在部分管线会被误读。

**硬规则**

1. 分辨率必须 2 的幂；非 2 的幂贴图不允许进管线（mipmap 与 ASTC 块对齐都会坏）。
2. BaseColor 与 Emissive 标 `colorSpace = SRGBColorSpace`；Normal/ORM 必须标 `NoColorSpace`。标错会导致「画面发灰」或「法线被当颜色二次编码」，这是 Web 端最高频的颜色事故。
3. 法线贴图统一 **OpenGL 约定（+Y 向上）**。Rodin / 多数 DCC 默认 DirectX（−Y），导入时必须翻转 G 通道，否则凹陷变凸起。
4. UV 岛间距 ≥ 4px（2048 贴图下），否则 mipmap 层级会串色；这是「远处出现脏边」的根因。
5. 像素密度统一 **512 px/m**（LOD0），单资产内波动 ≤ ±15%。不允许一块面板 2048、一颗螺丝也 2048。
   **【v1.2 变更】唯一例外：Art 岛。** 面板可见面单独成岛，允许 ≤ **2048 px/m**，须在资产 manifest 声明 `art_island: {px_per_m, uv_area_ratio}`。约束：① Art 岛 UV 面积占比 ≤ 8%；② 其余区域仍须 512 ±15%；③ 全资产加权平均密度 ≥ 512 px/m，由脚本核算。2048 是上限而非目标——4096² 全图集未压缩 64 MB、KTX2 约 10 MB，直接击穿 05A.3.2 预算（推导见 05A.6.1）。
6. 贴图不允许携带烘焙光照与投影。Rodin 输出的贴图几乎都带，见 05A.5。

**尺寸预算（单个 Physical Twin，LOD0 全集）**

| 项 | 上限 |
|---|---|
| BaseColor | 2048² ×1（共用 UV 图集） |
| ORM | 2048² ×1 |
| Normal | 2048² ×1 |
| Emissive | 512² ×1 |
| 未压缩合计 | ≈ 48 MB |
| KTX2 压缩后（ETC1S + UASTC 法线） | ≈ 5–6 MB |

**【v1.2 变更】运行时预算不变**（Art 合成进 BaseColor，不新增运行时贴图）。仅归档侧新增：

| 项 | 体积 |
|---|---|
| ArtMask 1024² RGBA（未压缩） | ≈ 4 MB |
| ArtMask KTX2（ETC1S，仅归档） | ≈ 0.4 MB |
| 对 runtime 包的影响 | **0** |

### 05A.1.3 光照与环境

**一套 HDRI 定生死。** 所有验收、所有截图、所有材质调参在同一个环境下完成，否则数值不可比。

- 环境：单张 studio HDRI（2K HDR，深黑背景 + 左前主柔光箱 + 右后条形轮廓光 + 顶部窄条光），经 `PMREMGenerator` 预过滤一次，赋给 `scene.environment`。**不做运行时环境探针、不做动态反射**。
- 主光：DirectionalLight，方向固定 `(-0.4, 0.8, 0.5)` 归一化，强度 2.2；唯一投影光源。
- 补光：DirectionalLight，`(0.6, 0.2, -0.4)`，强度 0.6，无阴影。
- 边缘光：DirectionalLight，`(0.2, 0.3, -0.9)`，冷青色 `#8FB6C8`，强度 0.8，只打轮廓，用来把深黑机身从深黑背景里剥离。
- 阴影：主光 `shadow.mapSize = 2048`，`PCFSoftShadowMap`，`shadow.bias = -0.0005`；地面用一张预烘焙的接触阴影/环形 AO 贴片，不跑实时 SSAO。
- 色彩管线：`renderer.outputColorSpace = SRGBColorSpace`；`toneMapping = ACESFilmicToneMapping`；`toneMappingExposure = 1.0`（允许 0.9–1.1，超出即视为调色事故）。
- 荧光出光：`UnrealBloomPass`，threshold 0.85 / strength 0.6 / radius 0.4。**不做叠加混合大面片来伪造辉光**——那是 overdraw 陷阱，移动端直接掉帧。

**【v1.2 变更】金属介质的过曝纪律。** 沉金（roughness 0.16–0.22）在轮廓光下会产生比 M3 更锐的长条高光，容易把「过曝像素占比 < 0.5%」顶穿。超限时的调整顺序固定，不得跳步：

1. 先缩小金属介质面积（`cu_ratio` 下调，见 05A.7.2 clamp 表）；
2. 再抬 roughness 下限（0.16 → 0.22，仍在工艺观感范围内）；
3. 最后才考虑拆长条形开窗为碎块。
   **禁止调整 `toneMappingExposure`**——它会同时破坏 118 ± 4 的中灰标定，属于调色事故而非修法。

**亮度标定（可量化，替代「看着差不多」）**

| 指标 | 目标 | 检法 |
|---|---|---|
| 中灰（18% 灰卡位） | 118 ± 4（sRGB 8bit） | 截图取样 |
| 高光过曝像素占比 | < 0.5% | 直方图 250 以上计数 |
| 黑位 | ≥ 8/255，不得死黑 | 直方图 0–7 计数 |
| 背景与机身分离度 | 边缘处 ΔL ≥ 12 | 灰度剖面 |
| **【v1.2 变更】** 丝印与阻焊的分离度 | ΔL ≥ 40 | 灰度剖面，取面板 Art 区内 5 处采样 |

### 05A.1.4 PCB Art 表面层：四种工艺质感的像素定义（【v1.2 变更】）

**为什么不做成新材质。** 三条理由，缺一不可：

1. 05A.1.1 的材质上限是 **Draw Call 与 shader 变体**预算，不是审美分类。面板加一个材质实例，就是多 1 个 DC、多 1 个编译变体，而 05A.3.2 的总 DC 只有 12。
2. 四种工艺的差异**全部落在贴图通道能力之内**：基色、粗糙度、金属度、clearcoat 都存在逐像素贴图。
3. 一旦开先例，下一次「再加一个」就没有拒的理由。预算靠的是不开口，不是靠每次重新谈判。

**像素属性表（LOD0，A 机位实测校准）**

| 工艺 | BaseColor（sRGB 8bit） | ORM.G roughness | ORM.B metalness | clearcoat / ccRough | ArtMask 通道 | 物理备注 |
|---|---|---|---|---|---|---|
| 阻焊（哑黑） | `#14161A` | 0.24–0.32 | 0.0 | 0.20 / 0.35 | R=0 | 聚合物涂层，有弱镜面但不金属 |
| 丝印（乳白） | `#E8E4DC` | 0.55–0.65 | 0.0 | 0.0 / — | R=1 | 油墨，比 M2 本体更哑 |
| 沉金（ENIG） | `#C8A250` | 0.16–0.22 | 1.0 | 0.0 / — | G=1, B=0 | 全资产唯一允许 roughness < 0.2 的非 M3 区域 |
| 露铜（裸铜） | `#B06A3C` | 0.30–0.45 | 1.0 | 0.0 / — | G=1, B=1 | 允许粗糙度区域差异模拟氧化，**不得**用 emissive 表现「通电」 |
| 基材（FR-4 侧边，可选） | `#3A3F42` | 0.70–0.85 | 0.0 | 0.0 / — | 全 0 | 仅侧边可见；不参与 ΔE 采样 |

**四条硬规则**

1. 表中色值必须进 `palette.json` 版控。改色 = 改验收基准，须重走 05A.4.5。
2. 沉金/露铜不得使用 emissive。发光只属于 M4，且只由状态机驱动（05A.4.4）。用发光表现「电路在运行」是叙事造假，见 05A.6 R3。
3. 丝印 clearcoat 必须为 0。开了会读成「塑料凸起」，与油墨工艺相反，且在侧光下产生不该有的镜面线。
4. 沉金与露铜的区分**只靠 BaseColor 色相 + roughness**，不靠法线凹凸。给丝印或焊盘加浮雕式法线是模拟「贴上去的贴纸」，真实工艺是平的。

## 05A.2 Rodin（Hyper3D）产出物的转换流程

### 05A.2.1 先定用途：Rodin 能做什么、不能做什么

| 用途 | 允许 | 条件 |
|---|---|---|
| 造型探索、概念提案、内部讨论 | ✅ | 截图必须标注 `CONCEPT ASSET / NOT PRODUCTION CAD` |
| Physical Twin（网页里的实体对应层）正式资产 | ❌ | 必须来自真实 CAD / Fusion 360；Rodin 结果不得作为生产型号依据 |
| Generative World 的程序化雕塑基础网格 | ✅ | 必须重做拓扑、UV、材质，不得直接用生成的贴图上线 |
| 销售图、预售封面、投资材料主视觉 | ❌ | 只用实体 CAD 渲染或实拍 |
| **【v1.2 变更】** 丝印 / 铜层 / 走线拓扑 / 阻焊开窗的图形来源 | ❌ | Rodin 网格无网络表、无层栈、无最小线宽语义，不存在到可 DRC 图层的映射路径（05A.2.4） |
| **【v1.2 变更】** 实体面板 / FR-4 装饰板版稿 | ❌ | 属 G2 制造，走 SVG → KiCad 分层 → DRC → 打样（05A.8） |
| **【v1.2 变更】** Web 侧 PCB Art 贴图（ArtMask / BaseColor Art 层） | ❌ | 由 visual_manifest 程序化生成（05A.7），美术与算法都不用手搓电路图 |

这一条与 §10 风险表「Rodin 概念误导买家」直接挂钩：**Rodin 资产一旦进入对外画面，必须携带阶段标注**。技术上线与合规标注是同一件事，不是两件事。

### 05A.2.2 处理链路（7 步，顺序不可调）

```
Rodin 原始输出 (glb/obj, 50k–400k tris)
  → ① 体检与归一（尺度/轴心/朝向/单位）
  → ② 拓扑清理（非流形/内部壳体/碎壳/重面）
  → ③ 结构减面（LOD0 目标面数，保硬边）
  → ④ 重做 UV（Rodin UV 一律弃用）
  → ⑤ 高模→低模烘焙（Normal / AO / Curvature）
  → ⑥ 重做 PBR 材质（Rodin 贴图降级为参考）
  → ⑦ 导出 glb + 压缩（meshopt / KTX2）
```

**① 体检与归一**

- 单位：统一 `1 unit = 1 m`；实体宽度按 CAD 实测（V1.1 目标 ≤ 240 mm，**待 CAD**）。
- 朝向：glTF 标准 +Y up，正面朝 +Z。
- 轴心（pivot）：底面中心，落地 y=0。Rodin 常把轴心丢在包围盒中心甚至世界原点偏移处，不修会导致旋转与落地全错。
- 变换必须 Apply（Blender `Ctrl+A` → All Transforms），否则减面比例与非均匀缩放会叠加出错。

**② 拓扑清理**

- `Merge by Distance` 0.0001 → 消重顶点。
- 删除内部壳体：`Select Interior Faces` → 删；AI 生成模型内部常有多层壳，直接拖垮烘焙和阴影。
- 删除碎壳：按 loose parts 拆分，删除面积 < 0.5 mm² 的悬浮碎片（生成模型边缘常见的「融化碎屑」）。
- 非流形边：`Select Non-Manifold` → 修或填；不允许带洞导出（会导致法线翻转与阴影漏光）。
- 退化面：`Dissolve Degenerate`。

**③ 结构减面**

| 目标 | 三角面上限 | 手段 |
|---|---|---|
| LOD0 | 30,000 | Decimate Collapse，先对平面件 Planar 减面，再整体 Collapse |
| LOD1 | 12,000 | 由 LOD0 再减，不从原始高模重减（保证轮廓一致） |
| LOD2 | 4,000 | 同上 |
| LOD3 | 1,200 | 同上，或远景 billboard 替代 |

减面纪律：**每一次减面后必须重算法线与硬边标记**，否则平滑着色会在棱角处糊成一片。硬边判定角 35°，分件缝一律 mark sharp，不靠 auto smooth 兜底。

**④ 重做 UV**

Rodin 的 UV 有三个确定性问题：岛重叠、接缝错位、密度严重不均。**不修，重做**。

- 分件 unwrap（机身/面板/旋钮/接口各自独立），Smart UV Project 角度 66°，island margin 0.02。
- 打包进单一 0–1 空间，目标像素密度 512 px/m ± 15%。
- **【v1.2 变更】** 面板可见面必须单独成岛，作为 Art 岛（≤2048 px/m，见 05A.1.2 硬规则 5）。与旋钮/侧壁混在同一岛里，Art 的密度例外会污染整张图集。
- 不启用 UDIM（Web 端不支持）。
- 完成后跑一次 UV 重叠检查，重叠面积必须为 0。

**⑤ 烘焙（Blender Cycles，CPU 亦可）**

| 通道 | 设置 | 说明 |
|---|---|---|
| Normal | Tangent space, +Y, 2048, margin 16px | 从 Rodin 原模型烘到减面模型 |
| AO | 2048, samples 128, distance 按 1 单位=1m 给 0.02 | 写入 ORM.R |
| Curvature | 可选，用于边缘磨损遮罩 | 不单独出图，只做材质遮罩 |
| BaseColor 重投影 | **Diffuse Color only（不带光照）** | 只用于把原贴图的宏观变化迁到新 UV |

关键：**BaseColor 重投影必须关掉光照**。用「Bake → Diffuse → Color only」或 Emit 技巧，绝不烘 `Combined`——那是把原图里的假光照焊死在新贴图上，之后任何重打光都会脏。

**【v1.2 变更】AO 烘焙与 Art 层的顺序冲突：** Art 图形是平的（05A.1.4 硬规则 4），不得在 Art 区产生 AO 暗边。做法：AO 烘焙时把 Art 岛排除（用 mask 屏蔽），Art 区 AO 恒为 1.0。否则丝印会被烘出「浮雕阴影」，正好造成 05A.1.4 要禁止的那种观感。

**⑥ 重做 PBR 材质**

Rodin 的贴图本质是「照片」，不是 albedo。正式资产按 M1–M5 的材质定义用节点重建，Rodin 贴图只取两样东西：宏观色相分布、局部磨损/污渍 mask。判据：**把环境光换成纯白 HDRI，材质观感不应发生色相跳变**；发生跳变说明贴图里还焊着光。

**【v1.2 变更】** Art 区（阻焊/丝印/沉金/露铜）**不吃 Rodin 贴图**。这四类是确定的工艺表面，色值来自 05A.1.4 表，任何来自生成模型的色相/磨损变化都会让 ΔE 标定失效。磨损只允许出现在非 Art 区。

**⑦ 导出与压缩**

- 应用全部修改器 → Triangulate → 删除相机/灯/空物体 → 导出 glb。
- 压缩用 `gltf-transform`（或 `gltfpack`）：
  - 几何：`meshopt`（优先，解码在 worker，比 Draco 快且 three.js 原生支持）。
  - 贴图：转 KTX2（见 05A.3）。
  - 目标体积：Physical Twin 桌面 ≤ 8 MB，移动 ≤ 4 MB；首屏关键资源 ≤ 3 MB。

### 05A.2.3 glb 与 usdz 的取舍

| 维度 | glb / glTF 2.0 | usdz |
|---|---|---|
| Web 实时渲染 | ✅ 主路线 | ❌ three.js USDZLoader 实验性，无压缩，体积是 glb 的 3–10 倍 |
| 几何压缩 | meshopt / Draco | 不支持 |
| 纹理压缩 | KTX2 (UASTC/ETC1S) | 不支持，只能 PNG/JPEG |
| AR（iOS Quick Look / Android Scene Viewer） | 不支持 | ✅ 唯一格式 |
| 客户/合作方离线审阅 | 需专用查看器 | ✅ 系统级打开 |
| 材质表达力 | 完整 PBR + 扩展 | 受限（不支持 three.js 侧自定义 shader） |
| 维护成本 | 管线一条 | **第二条独立管线**，面数与贴图需单独优化 |

**结论：glb 是唯一主资产格式；usdz 是按需派生的第二个交付物，不进 Web 包。**

- 仅在三种场景出 usdz：① AR 预览需求确认；② 合作方明确要「双击就能看」的审阅件；③ 线下展示机。
- usdz 独立优化：面数 ≤ 100k（USDZ 渲染器对高模宽容但加载慢）、贴图 ≤ 2K、单文件 ≤ 25 MB、无 shader 依赖。
- 不做 glb↔usdz 双向同步。usdz 由同一源工程（.blend）单独导出，改一次出两份，避免格式转换丢材质。

### 05A.2.4 Rodin 与电路语言的禁止清单（【v1.2 变更】）

Rodin 产出物**在任何情况下**不得转为 PCB Art 素材。四条技术事实：

| 事实 | 后果 |
|---|---|
| 网格无网络表（netlist） | 无法判定「这条线连的是哪两个节点」，也就无法校验是否为一条有意义的线 |
| 网格无层栈（layer stack） | 丝印层 / 阻焊层 / 铜层 / 钻孔层不可区分，无法分层导出 |
| 网格无最小线宽与间距语义 | 无法做 DRC；能画出来不等于能加工 |
| 网格是三角面，不是矢量化多边形 | 无法生成 Gerber；栅格化再矢量化会产成千上万个碎多边形，DRC 直接爆炸 |

推论（写死，不做例外）：

1. 禁止把 Rodin 生成的「电路纹理」贴到面板上冒充丝印——它连矢量都不是，缩放即糊。
2. 禁止用 Rodin 生成「PCB 造型的板子」当作面板结构依据——装配关系必须来自 CAD。
3. 禁止用 Rodin 输出训练/微调任何 Art 生成器——生成器的输入必须是 visual_manifest，不是网格。
4. 若某张 Rodin 概念图确实出现了像电路的纹样，进入对外材料前必须裁掉或标注为视觉示意（延续 §10「Rodin 概念误导买家」的处置口径）。

## 05A.3 LOD 与纹理压缩策略

### 05A.3.1 LOD 链

| LOD | 三角面 | 贴图 | 切换依据 | 备注 |
|---|---|---|---|---|
| LOD0 | 30,000 | 2048 | 屏幕包围球占比 > 18% | Hero 机位、特写 |
| LOD1 | 12,000 | 1024 | 6%–18% | 默认展示机位 |
| LOD2 | 4,000 | 512 | 1.5%–6% | 全景、舞台远景 |
| LOD3 | 1,200 | 256 | < 1.5% | 或直接 billboard 替代 |

**切换必须用屏幕空间占比，不用固定距离。** 固定距离在 FOV 变化、窗口缩放、移动端竖屏下全部失效。three.js `THREE.LOD` 的 distance 是相机距离，需要包一层自定义 `update(camera)` 按包围球投影尺寸切换。

- 迟滞（hysteresis）：切换阈值 ±10%，防止边界抖动导致 LOD 反复 pop。
- 过渡：0.2 s 内用 dither 透明度交叉淡入；深黑场景下硬切也可接受，但**同一帧内不得同时存在两个 LOD 的投影阴影**。
- LOD 一致性验收：LOD0/LOD1/LOD2 在同一机位下的剪影 IoU ≥ 0.96，不允许出现「换 LOD 时按钮消失」。
- 不允许任何资产绕过 LOD 链直接上线——这是硬门槛，见 05A.4.4 的自动化检查。

**【v1.2 变更】Art 层的 LOD 策略**

| LOD | Art 表现 | 处理 |
|---|---|---|
| LOD0 | 全量（2048 px/m Art 岛，最小特征 1.0 mm） | 正常 |
| LOD1 | 主干连线 + 节点 + 字标；二级连线减半 | 线宽**主动加粗**至 ≥2.0 mm，不靠 mipmap 自然衰减 |
| LOD2 | 只剩节点位置 + 主干（≥8 mm 段） | 文字降级为色块，不做字 |
| LOD3 | Art 全部丢弃 | 面板回到纯 M2 基色 |

两条纪律：

1. **线宽随 LOD 加粗，不随 mipmap 变淡。** 让 mipmap 自然处理的结果是「远处面板先糊成灰片，再突然变干净」，比直接丢掉更难看，也更难在验收里定位。
2. **Twin 的 Art 不随 Seed 变，World 的 Art 随 Seed 变。** 两者 LOD 策略不同：Twin 是固定贴图的 mip 链，World 是运行时参数（manifest + clamp）。混用会导致同一个 LOD 切换点出现「一边跳、一边不跳」。

### 05A.3.2 纹理压缩

| 平台 | 目标格式 | 说明 |
|---|---|---|
| 桌面 / WebGL2 | KTX2 → BC7（UASTC 转码） | 法线必须 UASTC，避免块状伪影 |
| 移动 / Android | KTX2 → ASTC 6×6（法线 4×4） | 6×6 是体积与质量的平衡点 |
| iOS | KTX2 → ASTC 6×6 | 同上 |
| 兜底（无 KTX2） | WebP 1024 + 关闭法线细节 | 只在能力探测失败时启用 |

- 编码：`toktx --uastc --uastc_quality 2 --zcmp 18`（法线）；`--etc1s --clevel 4 --qlevel 160`（albedo / ORM）。
- 加载：`KTX2Loader` + `MeshoptDecoder`，transcoder 路径随包部署（`basis_transcoder.js/wasm`），不走 CDN。
- mipmap：世界/机体纹理开启；UI 关闭；法线开启且 **normal 贴图不做 sharpening**。
- 各向异性：`min(4, renderer.capabilities.getMaxAnisotropy())`。机身有大量斜视角平面，这一项对边缘清晰度的影响大于贴图分辨率。
- 预算：单资产 KTX2 全集 ≤ 6 MB；整个 G2 场景首屏 ≤ 12 MB；总 Draw Call ≤ 12（同材质合并，旋钮等需独立动画的部件除外）。

**【v1.2 变更】ArtMask 的压缩与预算口径**

- ArtMask 用 **ETC1S**，禁 UASTC——它是遮罩不是法线，块状伪影在二值遮罩上会被阈值吃掉；UASTC 只是白花体积。
- ArtMask **不入 runtime 包**，只归档（≈0.4 MB）。上表三条预算（6 MB / 12 MB / 12 DC）**全部不变**。
- 若将来确需让 ArtMask 进包（例如做调色板热切换），必须走一次预算评审并重跑 05A.4.4 性能检；不得由美术或前端自行加入。

| 维度 | 指标 | 阈值 |
|---|---|---|
| 比例 | 正交视图与渲染轮廓重叠偏差 | < 2 mm（1:1 实物比例） |
| 控件位置 | 旋钮/按键中心位置误差 | < 1.5 mm |
| 颜色 | 5 个基材采样区 + 4 个介质标定块，ΔE2000（同一 HDRI 下，对比 R4 / R6；口径见 05A.4.5） | ≤ 3.0 |
| 材质 | metalness / roughness 与 R5 数值偏差 | ≤ 0.05 |
| 光照 | 中灰 / 过曝 / 黑位 | 见 05A.1.3 表 |
| 法线 | 法线朝向一致性（法线贴图 + 几何） | 无翻转面，无「凹陷变凸起」 |
| LOD | 相邻 LOD 剪影 IoU | ≥ 0.96 |
| 回归 | 版本间截图 SSIM（同机位） | ≥ 0.985；否则 ΔE 均值 ≤ 2.5 |
| **【v1.2 变更】** Art 覆盖率（Twin） | 丝印 + 金属介质在面板可见面的面积占比 | 与 R6 版稿的**相对**偏差 ≤ 5% |
| **【v1.2 变更】** Art 最小特征 | 世界尺度最小线宽 / 最小字高 | LOD0 ≥ 1.0 mm；LOD1 ≥ 2.0 mm |
| **【v1.2 变更】** 丝印 / 阻焊对比 | ΔL（同 HDRI，面板 Art 区 5 处采样） | ≥ 40 |
| **【v1.2 变更】** 跨 Seed 比较 | 不同 `visual_seed` 之间的截图 SSIM | **禁止**作为合格判定依据；只允许作分布统计 |

**「采集 5 个采样区」的位置规则（【v1.2 变更】）**：5 个区必须全部落在**无 Art 覆盖的基材区**，且在 R5 里固定坐标、随版本号锁定。生成器必须读取 `sampling_zones.json` 作为硬禁区（见 05A.4.5 第 1 条）。Art 覆盖率一旦侵入采样区，ΔE 会「合法地」超标——那是验收口径坏了，不是颜色坏了。

### 05A.4.3 四段体验的视觉状态（必须与音乐状态同源）

| 状态 | emissive 强度 | 环境光强度 | 相机 | 允许的粒子 |
|---|---|---|---|---|
| Locked | 0.0–0.15（仅低位呼吸） | 0.6 | 缓慢环绕 | 无 |
| Generate | 0.4 → 1.2（随 Seed 生成逐级点亮） | 0.8 | 推近至 Hero | ≤ 300 |
| Perform | 0.6–1.6（跟随控件/参数） | 1.0 | 稳定 3/4 机位 | ≤ 800 |
| Crack / Archive | 1.8（瞬时过曝）+ 结构错位 | 1.2 → 0.4 | 快速位移后归位 | ≤ 1200，单帧 |

每个视觉事件必须有对应音乐或操作原因；**静止与爆发的对比度靠曝光与 emissive 拉，不靠堆粒子**。

**【v1.2 变更】Art 层不参与状态动画。** 阻焊/丝印/沉金/露铜是工业表面，四段体验中**恒定不变**。动态只发生在 M4 荧光与 Generative World 的光路上。理由：一旦让 Art 随状态变色或发光，它就从「器物表面」变成「屏幕」，工业考古的叙事立刻塌掉，同时也会破坏 05A.4.5 的介质标定。

### 05A.4.4 验收流程

1. **资产入库检**：面数 / UV 重叠 / 贴图分辨率与色彩空间 / 非流形 / 轴心 / 单位，全部脚本化，不过检不入库。
2. **材质检**：在固定 HDRI 下按 R4 四机位出图，跑 ΔE 与亮度直方图脚本。
3. **LOD 检**：三档 LOD 同机位出图，算剪影 IoU。
4. **性能检**：目标机型（桌面集显 + 一台中端 Android）跑 60 s 录制，统计帧时间 P95 与 GPU 时间；Twin 部分 GPU 预算 ≤ 4 ms/帧。
5. **标注检**：概念资产阶段标注是否随资产一起进入页面。
6. 六项全过才签核。任何一项「留到上线前再修」＝ 不通过。
7. **【v1.2 变更】Art 检**：禁区断言（0 侵入）+ 介质标定块 ΔE ≤ 3.0 + 覆盖率相对偏差 ≤ 5% + 最小特征达标 + 同 Seed 双次生成贴图 sha256 一致。五项全过才算 Art 合格；软件渲染「看起来对」不算。

### 05A.4.5 PCB Art 层的验收与 ΔE2000 / SSIM 的适用边界（【v1.2 变更】）

**问题本体。** 05A.4.2 的 ΔE ≤ 3.0 是对固定参考图 R4 做采样区比对，SSIM ≥ 0.985 是版本间回归。但 PCB Art 的图案在 Generative World 层**随 Seed 变化**。若把 Art 区域一并纳入这两项，同一个资产在不同 Seed 下会「合法地」失败，验收标准就被 Seed 绑架了——这是口径问题，不是质量问题。

**结论：按层拆开，两层用两套指标。**

| 层 | Art 来源 | 是否随 Seed 变 | 适用指标 | 不适用指标 |
|---|---|---|---|---|
| Physical Twin（实体对应层） | R6 实体面板版稿导出的固定绘图层 | 否（同一 Release 固定） | ΔE2000 ≤ 3.0、SSIM ≥ 0.985、覆盖率、最小特征、ΔL | — |
| Generative World（生成世界层） | `visual_manifest` 程序化（05A.7） | 是 | 覆盖率、最小特征、密度 clamp、禁区 0 侵入、结构可读性 | **ΔE 全图比对、跨 Seed SSIM** |

**六条判定规则**

1. **采样区禁区。** 生成器读 `sampling_zones.json`，Art 不得侵入；CI 断言侵入面积 = 0。产出即失败，不设容忍度。
2. **ΔE 只判介质，不判图案。** 4 个 10×10 mm **介质标定块**（阻焊 / 丝印 / 沉金 / 露铜）位置固定、随 R5 版控、不随 Seed 变，只测「这四种工艺的颜色准不准」。ΔE2000 ≤ 3.0 的阈值不变，但**判定对象从「5 个任意采样区」明确为「5 个基材区 + 4 个介质标定块」**。
3. **SSIM 只在同 Seed、同 manifest、同 generator_version 下有效。** 跨 Seed 的 SSIM 只作分布统计，永不进入合格判定。任何「跨 Seed SSIM 掉到 0.9 所以要修」的结论都是错的。
4. **跨 Seed 的结构指标另立**（不在 SSIM 里找补）：Art 覆盖率相对偏差 ≤ 5%、最小特征达标、`lines_per_dm²` 不超 clamp 上限、禁区侵入 = 0、16 个节点在 LOD1 下仍可辨（间距 ≥ 8 mm）。
5. **过曝归属。** 沉金/露铜的高光须计入 0.5% 全局过曝预算。超限时按 05A.1.3 的三步顺序修，**不得动 exposure**（会同时破坏 118 ± 4 中灰与 ΔE）。
6. **不对等声明。** ΔE / SSIM 通过 ≠ 视觉正确，更 ≠ 实体可制造。前者只说明渲染与参考一致；后者由 05A.8 的 DRC 与打样证明。两者的放行条件不得互相顶替。

**为什么不做全图 ΔE。** 全图 ΔE 对图案差异极度敏感（一条线移 1 mm 就能顶穿阈值），会把「Seed 变化」误判成「颜色错误」。做全图 ΔE 的前提是参考图与产物图案完全一致——这只在 Twin 层成立。

**不可修复清单（出现即换路线，不要修）**

- 控件数量、位置、比例与真实设计不符 → Rodin 不能做 Physical Twin，直接用 CAD。

- **【v1.2 变更】** 主体纹样已经是电路拓扑（走线分级、过孔阵列、元件本体）→ 不是「修图案」，是整层作废，回到 visual_manifest 重生成。

**单资产人力基线**：一个 Rodin 概念件 → 可上线的 Web 资产，约 **5–6 人日**（清理 1.5 + 减面 UV 1 + 烘焙材质 2 + 集成验收 1），不含 CAD 建模与动画。预算按此排，不按「AI 生成很快」排。

## 05A.6 PCB Art / Circuit Language 的三维表达规则（【v1.2 变更】）

> 依据：产品册 v1.2 §5.4。核心矛盾一句话：**要让人看出「这里有电路语言」，但不能让人以为「这是真的电路图」。**
> 本节只解决「怎么表达」。视觉语法怎么程序化在 05A.7；实体怎么造在 05A.8；怎么验收在 05A.4.5。

### 05A.6.1 尺度推导：为什么不能复刻真实电路

这不是画风选择，是贴图预算的算术结果。

| 参数 | 数值 | 推导 |
|---|---|---|
| 基础 texel 密度 | 512 px/m | 05A.1.2 硬规则 5 |
| 1 texel 世界尺寸 | 1.95 mm | 1 / 512 m |
| Art 岛允许密度 | ≤ 2048 px/m | 05A.1.2 例外条款 |
| Art 岛 1 texel | 0.49 mm | 1 / 2048 m |
| Art 岛 UV 占用 | ≤ 8% | 面板 240×160 mm 在 2048² 图集下约 161k px ≈ 3.8% |
| 最小可表达特征（2 texel，抗 mipmap 与最近邻） | **≈ 1.0 mm** | 2 × 0.49 |
| 板厂常规丝印线宽 | 0.15 mm | 行业常规能力 |
| 板厂常规走线宽度 | 0.10–0.20 mm | 同上 |
| 复刻 0.15 mm 丝印所需密度 | **≈ 13,300 px/m** | 2 texel = 0.15 mm |
| 差距 | **6.5 倍** | 13,300 / 2,048 |
| 4096² 全图集代价 | 未压缩 64 MB / KTX2 ≈10 MB | 击穿 05A.3.2 的 6 MB 预算 |

**读法：** 3D 侧 Art 的最小特征比真实 PCB 工艺粗 6.5 倍。所以它只能表达「图形语法」，不能表达「电路工艺」。产品册 §5.4 那句「装饰图不能被误当成真实电子走线」，在技术上是**可计算的**——不是道德要求，是分辨率不够。

**由此得出一条可执行判据：** 任何 Art 特征的世界尺度 ≥ 1.0 mm，天然就读不成「真走线」；任何试图做到 < 0.5 mm 的方案，必然要动贴图预算，必须重新评审而不是偷偷放大 UV 岛。

### 05A.6.2 层分工：Twin 固定，World 变化

最容易出错的地方：把「实体面板的图案」和「3D 世界的图案」当成同一张图。

| 层 | Art 来源 | 是否随 Seed 变 | 权威依据 | 验收 |
|---|---|---|---|---|
| Physical Twin | R6 版稿导出（SVG 分层 → 贴图） | 否，同一 Release 固定 | 实体面板打样 | ΔE ≤ 3 + SSIM ≥ 0.985 + 覆盖率 |
| Generative World | `visual_manifest` 程序化（05A.7） | 是 | manifest + generator_version | 结构指标（05A.4.5 规则 4） |

三条推论：

1. Twin 的 Art 必须与实体**1:1**。同一个 Release 的所有用户看到同一块面板图案——这与实体首批统一 PCB 是一致的，不是偷懒。
2. World 的 Art 按 Seed 变。用户输入不同 Serial，看到的光路、节点、密度不同——这是「Serial 解锁一个世界」的视觉证据。
3. **两者不一致不是 bug。** 但必须在文档与页面说明里写清楚：Twin 是器物，World 是生成物。若有人在验收里拿 World 的截图去比 Twin 的版稿，是口径错误（05A.4.5 规则 3）。

### 05A.6.3 五条表达硬规则

**R1｜不复刻真实电路拓扑。**
禁止出现：IC 引脚扇出（fanout）、过孔阵列（via farm）、泪滴（teardrop）、按电流分级的线宽（电源/信号/差分对）、阻抗控制线（蛇形等长）、丝印框图配引脚编号。
允许：正交折线、圆角拐点、圆形/方形节点、抽象焊盘轮廓、单一线宽。
判据：**把图给一个硬件工程师看，他的第一反应不能是「这板子画错了」，而应是「这是图形」。** 前者说明我们在冒充，后者才达标。

**R2｜不做假元件，不写假网络名。**
禁止：渲染贴片电阻/电容/芯片本体、出现 `VCC` `GND` `CLK` `RESET` `TX` `RX` 等真实网络名、出现非产品型号的料号。
允许字符集（闭合枚举，不许扩）：`SERIAL`、版本号（如 `v1.2`）、16-step 编号 `0–F`、`GENERATE` `MODIFY` `CRACK`、型号占位（**仅当 CAD 已定**）。
理由：文字是最容易被读成「真实信息」的元素。面板上出现一个假型号，等于在产品里埋了一句假话。

**R3｜不表现不可见工艺，不用发光假装通电。**
禁止：X 光透视内层铜、剖面展示层叠、用 emissive 沿走线跑光模拟「电路在工作」、用扫描线表现「信号传输」。
允许：M4 的荧光点（状态反馈，05A.4.4）、世界层的光路（**只在 Generative World，且是粒子/光线，不是贴图发光**）。
理由：Art 是器物表面，不是状态显示器。一旦让它「亮起来」，就同时破坏了 05A.4.3 的状态分层和 05A.1.4 的介质标定。

**R4｜尺度诚实：最小特征 ≥ 1.0 mm。**
见 05A.6.1。低于此值不是「更精细」，是「必然糊」。LOD1 起线宽主动加粗到 ≥2.0 mm（05A.3.1）。

**R5｜实体未打样前，Art 层必须自带阶段标注。**
Twin 的 Art 层在 R6 就位前，资产 manifest 与页面均标 `ART LAYER: DESIGN DRAFT / NOT MANUFACTURING DATA`。
与 05A.2.1 的 `CONCEPT ASSET / NOT PRODUCTION CAD` 同级，属同一套对外表述纪律（§12）。标注不随资产单独剥离——打包时丢失即为不合格（同 05A.4.4 第 5 项）。

### 05A.6.4 性能预算

| 项 | 桌面（集显） | 中端 Android |
|---|---|---|
| Art 贴图合成（一次性，worker） | ≤ 250 ms | ≤ 600 ms（1024²）；首帧用 512² 占位 ≤ 80 ms |
| Art 增加的三角面 | 0 | 0 |
| Art 增加的 Draw Call | 0 | 0 |
| Art 增加的 GPU 时间 | ≤ 0.2 ms/帧 | ≤ 0.4 ms/帧 |
| 世界层光路：合并后三角面 | ≤ 2,048（≤256 实例 × 8 tris） | 同 |
| 世界层光路：Draw Call | 1（InstancedMesh 或 merged geometry） | 1 |
| 世界层光路 GPU 增量 | ≤ 0.6 ms/帧 | ≤ 1.2 ms/帧 |
| Overdraw | 光路必须不透明或 `alphaTest(0.5)`；**禁止 alpha blend 光带** | 同 |
| 粒子 | 沿用 05A.4.3 上限（Perform ≤ 800） | 同 |

四条纪律：

1. **光路不许用半透明面片叠。** 一条「发光通道」如果用三层 alpha 面片做，等于 3× overdraw，移动端第一个掉帧的就是它。要发光就走 emissive + bloom 阈值（05A.1.3）。
2. **光路必须是实例化或合并几何。** 256 条独立 mesh = 256 个 DC，直接顶穿 12 DC 预算。
3. **Twin 的 Art 完全烘进贴图，不建几何。** 任何「用挤出几何表现焊盘凸起」的方案一律否掉——真实工艺是平的（05A.1.4 硬规则 4），且几何会让 DC 与面数同时上涨。
4. **世界层的光路数量受 manifest 密度 clamp 约束**（05A.7.2），不由粒子系统自行决定。

## 05A.7 visual_manifest → 贴图与参数的程序化管线（【v1.2 变更】）

> 依据：产品册 v1.2 §5.4「统一生成原则」。该原则明确 **schema / 散列 / 域分离 / 测试向量均未冻结**，本节给的是**候选实现草案**，不得当作已实现标准对外表述。

### 05A.7.1 前提：与音乐 PRNG 隔离

| 约束 | 做法 | 后果（必须成立） |
|---|---|---|
| 视觉不改音乐 | `visual_seed` 独立派生，独立 PRNG 实例 | 改粒子数 / 材质 / 图案，`structure_hash` 不变 |
| 音乐不改视觉 | 音乐 PRNG 的消耗顺序不得被视觉模块读取 | 视觉重放不推进音乐流 |
| 两者可追溯 | manifest 记录 `generator_version` + `visual_seed` | 同一 Serial 同一版本 → 同一 manifest |

**`visual_seed` 派生（候选，未冻结）：**

```
visual_seed = HMAC-SHA256(key = engine_version, msg = "VISUAL\x00" + seed)[0..7]   // 8 bytes → 16 hex
```

- 域分离字符串 `"VISUAL\x00"` 是**占位**，与音乐侧的域分离方案一并设计，不得单独定稿。
- 禁止：直接用 `seed` 当 `visual_seed`；禁止用同一 PRNG 实例先后服务音乐与视觉。前者会让「换视觉就换音乐」，后者会让「粒子数改变节拍」。
- 本节所有内容在 `MANIFEST/0.1-draft` 阶段，**禁止在 G1 或对外材料中引为已实现**。

### 05A.7.2 图形语法四要素

manifest 候选 schema（字段名待冻结）：

```json
{
  "schema_version": "VM/0.1-draft",
  "visual_seed": "3C1A9F07B2D45E88",
  "generator_version": "SERIAL-VIS/0.1",
  "palette_id": "P1",
  "grid": { "cols": 4, "rows": 4, "pitch_mm": "待 CAD", "origin": "panel-bottom-left" },
  "nodes": [
    { "step": 0, "cell": "A1", "glyph": "g03", "scale": 0.8, "medium": "silk" }
  ],
  "edges": [
    { "a": 0, "b": 1, "kind": "seq",   "bend": "orth" },
    { "a": 0, "b": 6, "kind": "chord", "bend": "orth" }
  ],
  "density": { "lines_per_dm2": 12, "cu_ratio": 0.18, "silk_ratio": 0.06 },
  "motif_version": "MOTIF/0.1",
  "atlas_keys": ["glyph.g03", "num.0A", "wordmark.serial"]
}
```

**要素一：节点布局**

| 规则 | 值 | 为什么 |
|---|---|---|
| 栅格 | 16 节点映射 4×4 工程栅格 | 与 16-step 一一对应，用户能数出来 |
| 栅格 pitch 与原点 | 与实体面板丝印栅格一致（**待 CAD**） | Twin 必须 1:1；栅格不一致 = 装配图对不上 |
| 抖动 | 节点中心在 ±0.25 pitch 内偏移，由 `visual_seed` 决定 | 全对齐像表格，全随机像噪声；小幅抖动才有「制造公差」的观感 |
| 介质分配 | `medium` ∈ {silk, mask-open, copper}，由 Seed 选 | 同一节点在不同 Serial 下可能露铜或只留丝印 |

**要素二：连线规则**

| 层级 | 规则 | 上限 |
|---|---|---|
| 主干 | 序列边 `step i → i+1`，正交折线，拐点圆角 ≤ 0.3 × 线宽 | 最多 15 条（闭合环另算） |
| 二级 | 音程边：interval class 1–6 映射到连接距离档，`visual_seed` 在候选集内选 | ≤ 8 条 |
| 禁止 | 任何交叉判定之外的「装饰性绕线」；任何穿过控件禁区或丝印文字框的线 | — |

主干固定、二级随 Seed——这个设计是刻意的：**主干保证「任何 Serial 都看得出这是 16-step 序列」**，二级保证「不同 Serial 长得不一样」。若全随 Seed，用户会怀疑产品没有核心结构；若全固定，用户会觉得 Serial 无用。

**要素三：图形密度（必须 clamp）**

Seed 可以决定密度，但**不能决定性能**。派生值一律先 clamp 到平台预算：

| 参数 | LOD0 上限 | LOD1 | LOD2 | LOD3 |
|---|---|---|---|---|
| `lines_per_dm²` | 12 | 8 | 4 | 0（Art 丢弃） |
| `cu_ratio`（沉金+露铜面积占比） | ≤ 0.18 | ≤ 0.12 | ≤ 0.06 | 0 |
| `silk_ratio`（丝印面积占比） | ≤ 0.08 | ≤ 0.06 | ≤ 0.03 | 0 |
| 二级连线数 | ≤ 8 | ≤ 4 | 0 | 0 |
| 单条直线段最小长度 | ≥ 2.0 mm | ≥ 4.0 mm | ≥ 8.0 mm | — |

对称约束：**视觉不改变 `structure_hash`，Seed 也不改变性能预算。** 前者是产品承诺，后者是工程底线，两条都得钉死。

**要素四：色系（固定枚举，不生成新色）**

| ID | 语义 | 主色 | 用途 |
|---|---|---|---|
| P1 | 冷青荧光 | 丝印 `#E8E4DC` / 强调 `#8FB6C8` | 默认，与边缘光同源 |
| P2 | 铜金 | 丝印 `#E8E4DC` / 强调 `#C8A250` | 沉金占比高的 Seed |
| P3 | 乳白低饱和 | 丝印 `#E8E4DC` / 强调 `#B8B2A6` | Crack / Archive 段的降饱和态 |

- Seed **只选 ID，不混合、不插值、不生成第四套**。任何「按 Seed 微调色相」的做法都会让 05A.4.5 的介质标定块失效。
- 色值表在 `palette.json` 版控，改色 = 改验收基准。

### 05A.7.3 哪些进图集，哪些必须程序化

先分清两种「图集」，否则会做出「有一张 atlas 但没用」的假优化：

- **素材图集（source atlas）**：生成期的贴图素材集合（glyph、数字、字标、模板、噪声），离屏、可换、按需拼。
- **运行时图集（runtime atlas）**：进 GPU 的合并贴图。本章**不建**——Art 在生成期就合成进 BaseColor 了，再挂一张 atlas 只是多一次采样和一条 UV 通道，换不来 DC 收益（面板本就 1 个 DC）。

| 元素 | 随 Seed 变？ | 复用度 | 进素材图集？ | 运行时形态 |
|---|---|---|---|---|
| 节点字形（8–12 种） | 否（只选） | 高 | ✅ 512²，4×4 tile | 合成进 BaseColor / ArtMask |
| 数字与字母 `0–9` `A–F` | 否 | 高 | ✅ 64 px tile（SDF 或位图） | 同上 |
| 产品字标 / 版本串 / 型号 | 否 | 高 | ✅ **整串一张**（不做逐字排） | 同上 |
| 焊盘 / 过孔 / 连接器轮廓模板（≤6 种） | 否 | 中 | ✅ | 同上 |
| 磨砂 / 氧化 / 纸基噪声（无缝平铺） | 否 | 高 | ✅ 512²，可平铺 | 同上 |
| **连线路径与拐点** | 是 | 低 | ❌ **必须程序化** | worker 光栅化 + SDF |
| **节点坐标布局** | 是 | — | ❌ | manifest 数据，不烘图 |
| **铜岛 / 阻焊开窗多边形** | 是 | 低 | ❌ | 逐点多边形填充 |
| **密度调制 / LOD 线宽** | 是 | — | ❌ | 运行时参数 |

**三条判据（可复用到后续任何 Art 元素）**

1. **形状集合有限且不随 Seed 变** → 进素材图集。字形、数字、字标属于此列。
2. **拓扑随 Seed 变**（路径、多边形、布局）→ 必须程序化。任何预烘 tile 都会在第二张 Seed 上露出重复，用户第一眼就看穿。
3. **需要跨 LOD 连续缩放** → 必须程序化或 SDF。位图 tile 在 LOD2 会糊成灰块，而 SDF 能保持边缘。

**关于文字的一条硬约束：** 面板文字只能从素材图集取，**禁止由生成模型或字体轮廓现场生成**。这与 05A.5 #14 / #17 直接对应——AI 生成的文字幻觉在面板上是最难发现、也最伤信任的缺陷。

### 05A.7.4 生成管线（7 步，顺序不可调）

```
visual_manifest
  → ① 载入禁区（sampling_zones.json / control_keepout.json）
  → ② 栅格落位 + 节点抖动（clamp 后）
  → ③ 主干 → 二级连线光栅化（2× 超采样后下采样）
  → ④ 从素材图集贴字形 / 数字 / 字标 / 模板
  → ⑤ 介质分区合成（阻焊底 → 丝印 → 金属介质）
  → ⑥ 输出 ArtMask(R/G/B) + BaseColor overlay
  → ⑦ 计算并记录 hash
```

关键约束：

| 步骤 | 约束 | 违反后果 |
|---|---|---|
| ① | 禁区为硬约束，非建议 | ΔE 采样被 Art 覆盖，验收口径失效 |
| ③ | 在 2048 px/m 网格上光栅化，再 2× 超采样下采样 | 直接按 512 px/m 画，线宽不足 2 texel，必然断裂 |
| ⑤ | 介质叠放顺序固定（底→丝印→金属） | 顺序错会导致丝印被金属覆盖，或阻焊吃掉丝印边缘 |
| ⑦ | hash 写入 asset manifest | 无法做同 Seed 双次生成的一致性断言 |

**确定性要求**

- 同一 `(visual_seed, generator_version, palette_id, LOD)` → 输出逐字节相同；CI 断言两次生成 PNG 的 sha256 一致。
- `generator_version` 一变，hash 全变，属**预期行为**：必须同步更新回归基线，不得为了让 SSIM 过而冻结旧生成器。
- 不做「随机种子微调直到好看」——那会让同一 Serial 在不同机器上产出不同图案，直接违背 `Same Serial → Same Structure` 的延伸承诺。

## 05A.8 边界：实体 PCB Art 属 G2 制造，不属 Rodin 资产管线（【v1.2 变更】）

> **一句话结论：实体 PCB 的艺术化是制造任务，走 G2；Rodin 只做概念造型，永远不产出可制造图形。**

### 05A.8.1 工作分解

| 环节 | 产出 | 工具 / 责任 | 验收 | Rodin 可否参与 |
|---|---|---|---|---|
| 概念造型探索 | 概念网格 / 概念渲染 | Rodin + TA | 目视 + 阶段标注 | ✅ **仅此一项** |
| 平面视觉语法 | `visual_manifest` + 素材图集 | TA（代码） | manifest 一致性 + 结构指标 | ❌ |
| Web Art 贴图 | ArtMask + BaseColor Art 层 | TA（worker 生成） | 05A.4.5 | ❌ |
| 实体面板 / PCB 版稿 | SVG → KiCad 分层（丝印/阻焊/铜/钻孔） | 硬件 + 工业设计 | DRC + 制造预览 + 1:1 打样 | ❌ |
| 生产文件 | Gerber / 钻孔 / BOM | ECAD | 板厂工艺能力 | ❌ |
| 面板结构（尺寸、紧固、干涉） | CAD 装配 | Fusion 360 | 装配检查 | ❌ |

### 05A.8.2 四条硬规则

1. **不存在从 AI 网格到可 DRC 图层的映射路径。** Rodin 网格没有网络表、没有层栈、没有最小线宽语义（05A.2.4 四条技术事实）。任何「把模型转成丝印」的尝试，本质是把渲染当制造数据。
2. **两套验收，互不替代。** 实体 Art 的验收是 DRC、1:1 打样、手感与识别测试（§5.4 / §9）；Web Art 的验收是 05A.4.5 的 ΔE / SSIM / 覆盖度。**ΔE 通过不能证明可制造，DRC 通过也不能证明视觉正确。** 两条线各自签核，分别留档。
3. **顺序固定：电气 DRC → 丝印分层 → 制造预览 → 1:1 打样。** 3D Art 可在 DRC 之后并行推进，但**不得以 3D 效果倒逼电气改板**；确需改板，整链重跑 DRC，不许局部打补丁。
4. **首批量产统一 PCB、统一丝印，不按 Seed 逐张定制**（§5.4）。个性化只在三种条件下成立：限定编号批次、联名批次、可更换的非功能装饰板。**Web 侧可以逐 Seed 不同——这不是不一致，是两条产线不同的成本结构。** 实体换一次版要开一次钢网、走一次 DRC；网页换一次图案只需重跑一次 worker。

### 05A.8.3 目录与产物隔离

```
assets/web-art/        ← ArtMask、生成器、palette.json、素材图集（仅 Web）
hardware/panel/        ← SVG 分层、KiCad 工程、DRC 报告、打样照片（仅制造）
```

- 两个目录**禁止互相引用**。CI 加一条断言：`hardware/panel/` 下不得出现 `assets/web-art/` 的产物，反之亦然。
- 唯一允许的共享物是**语法文档**（manifest 字段定义、调色板色值、栅格规则），不是文件。共享文件是最容易造成「渲染稿被当成生产稿」的路径。
- 对外材料引用实体 Art 时，只能用打样件实拍或 R6 版稿截图，不得用 Web 渲染图代替（延续 §10「Rodin 概念误导买家」的同一逻辑）。

### 05A.8.4 与 G1 / G2 / G3 的挂接

| 阶段 | Art 相关交付 | 明确不做 |
|---|---|---|
| G1 | 无。G1 页面只有「由 hash 派生的静态色块/几何」（§08） | 不做 Three.js、不做 Art 生成器、不做 PCB Art 设计或制板 |
| G2 | ① 首件可制造的艺术面板/PCB 版稿（含 DRC 记录）② Twin 的固定 Art 层（依 R6）③ `visual_manifest` 草案 + 生成器 v0.1 ④ 一件实物打样 | 不做按 Seed 逐张定制的实体板；不做 G3 的完整产品工程 |
| G3 | 完整量产版稿、正式 Release 图案、可选限量批次 | — |

**G2 的 Art 验收必须分开记录**（§5.4 明确要求）：电路可靠性、光学效果（材质观感）、成本验证、视觉一致性（05A.4.5）四项各自留证据，不得合并成一个「Art 通过」。
